# 开局前 XGBoost 模块规格与当前效果对比

状态：M14 开局前最低门槛最终验收通过；M15-M20 首杀后数据、基线、调参、评估、解释与接口验收通过；M0 人工抽查和 M3 tick 偏移证据仍保留为非阻塞缺口
更新日期：2026-08-20

## 1. 项目目标

第一阶段只完成一个问题：在每回合购买完毕、冻结时间结束、正式交火开始前，根据当时可获得的信息，预测 CT 赢得该回合的概率。

模型输出：

```text
ct_win_probability = 0.00 ~ 1.00
t_win_probability = 1 - ct_win_probability
```

这一阶段的目标不是单纯追求最高准确率，而是建立一个数据正确、没有泄漏、可复现、概率可信、能够解释和使用的 XGBoost 基线。完成该阶段后，才能复用同一结构开发首杀后胜率和实时胜率。

## 2. 当前假设

1. “开局前”的准确时点为 `freezeTimeEndTick` 附近，而不是购买武器之前。
2. 主指标为 AUC 和 Log Loss；Accuracy、Brier Score、ECE 作为辅助指标。
3. 训练集、验证集、测试集继续按 ESTA `matchId` 分组，使同一系列赛的地图不会跨集合。
4. 战队和选手身份特征暂不加入；完成 M2 和开局前基线复验后再单独决定。
5. 第一阶段只使用 XGBoost；LightGBM 在 XGBoost 验收后再作为对比模型。
6. 本规格中的数值目标是项目阶段门槛，不是所有 CS 比赛数据都必须达到的通用标准。

- Accuracy 提升约 12.30 个百分点。

- Log Loss 下降约 0.1009，降幅约 14.6%。
- Brier Score 下降约 17.8%。

所以当前模型已经有真实预测能力，主键、数据质量、泛化差距和统一测试评估均已通过最低门槛；四个核心测试指标仍未达到阶段目标。

## 4. 模块拆分与验收目标

### M0：问题定义与时间点

目的：明确模型在什么时刻预测，以及当时哪些信息允许使用。

输入：ESTA 回合字段和帧。  
输出：一页数据定义，明确标签、预测时点、允许特征和禁止特征。

验收目标：

- 标签严格为该回合最终赢家，`CT=1`、`T=0`。
- 快照来自 `freezeTimeEndTick` 最近帧。
- 禁止使用首杀、伤害、下包、回合结束原因等未来信息。
- 随机抽查至少 20 个回合，人工确认快照时间点合理。

当前效果：代码已使用 `freezeTimeEndTick`，但没有人工抽查记录和正式特征边界文档。  
状态：部分完成。

### M1：环境与可复现入口

目的：保证隔一段时间后仍能用同样环境运行。

输入：Conda `game` 环境。  
输出：固定版本文件、环境检查命令和一条完整运行入口。

验收目标：

- 固定 Python、pandas、scikit-learn、XGBoost、pyarrow、joblib 版本。
- 新建同版本环境后可读取 Parquet、训练并加载模型。
- 同一随机种子重复训练，AUC 与 Log Loss 差异不超过 0.002。

当前效果：`environment.yml` 和 `requirements-lock.txt` 已固定 Python 3.10.20、
XGBoost 3.2.0 及全部核心依赖版本；M14 清单验证运行环境完全匹配。统一 PowerShell
入口可以使用指定 Python 复验或完整重建。
状态：完成。

### M2：原始数据读取与唯一主键

目的：让每个系列赛、地图和回合都能被唯一识别。

输入：LAN/online 的 1,558 个 `.json.xz`。  
输出：包含 `series_id`、`game_id`、`round_id` 的标准 rounds/kills 表。

推荐定义：

```text
series_id = ESTA matchId
game_id   = demo 文件名或 demoId
round_id  = game_id + round_num
split     = 按 series_id 分组
```

验收目标：

- `game_id + round_num` 重复数为 0。
- 每个击杀事件能够准确关联到一个地图中的一个回合。
- 原始文件数、成功解析数、失败文件数均有日志。
- LAN 和 online 的来源字段保留到质量报告中。

历史问题：782 个 `matchId` 对应 1,558 张地图；旧的 `round_id = matchId + round_num` 产生 18,955 条重复记录，8,179 个重复键存在标签冲突。

当前效果：代码已改为 `series_id + game_id + round_id`；主键回归测试通过。M2 重建得到 41,076 个唯一回合；M4.2 排除 2 条无效开局快照后，当前标准表为 41,074 个唯一回合和 268,640 条击杀。重复主键、标签冲突和孤立击杀均为 0。  
状态：完成。

影响说明：开局前模型没有使用 ID 作为特征，且按系列赛切分，因此当前开局前结果仍可作为临时基线；首杀表按错误键关联，现有首杀后结果不能作为最终结果。

### M3：开局前快照提取

目的：从每个回合提取一个稳定的购买结束快照。

输入：每回合帧列表和 `freezeTimeEndTick`。  
输出：每个有效回合恰好一行快照。

验收目标：

- 每个 `game_id + round_num` 最多一行。
- 没有帧的回合被记录并跳过，不静默填充错误数据。
- 最近帧与目标 tick 的距离有统计报告，例如中位数、95 分位数和最大值。
- 抽查样本中双方人数、经济和武器数量与原始 JSON 一致。

当前效果：已实现最近帧选择；M4.2 要求最近帧为 5v5，完整数据产出 41,074 行并排除 2 条无效快照。已有异常样本核验记录，但尚缺全量 tick 距离分布报告。  
状态：部分完成。

### M4：数据质量检查

目的：在训练前阻止错误数据进入模型。

输入：标准回合表。  
输出：自动化质量报告和失败退出码。

验收目标：

- 主键重复为 0，核心字段缺失为 0。
- `ct_win` 只能为 0/1，双方存活人数在 0 到 5 之间。
- 金钱、装备价值、护甲和武器数量均在合理范围。
- 比分、回合号和获胜标签的基本逻辑检查通过。
- 质量检查失败时停止生成训练数据。

当前效果：质量闸门已接入 `make_dataset`，严重错误会阻止生成训练表。M4.1 完成异常来源调查；M4.2 按玩家规范化 inventory，并排除非 5v5 快照。全量报告中 error=0、warning=0，只剩 47 个无有效击杀回合的信息记录。  
状态：完成。

### M5：训练/验证/测试划分

目的：防止同一系列赛信息泄漏到多个集合。

输入：清洗后的回合表。  
输出：固定的 train/val/test 分组清单。

验收目标：

- 按 `series_id` 做 70/20/10 划分。
- 三个集合的系列赛交集均为 0。
- 分组清单保存到文件，不因重新生成特征而变化。
- 各集合地图和标签分布有对比报告。

当前效果：代码已按 `series_id` 划分；完整数据为 547/156/79 个系列赛，三个集合交集
为 0。开局前与首杀后数据的系列赛 split 完全一致；M14 已把 782 个系列赛映射保存为
`reports/esta_full_m14/split_assignments.csv`。
状态：完成。

### M6：特征工程

目的：只使用开局时可获得且有清晰含义的特征。

输入：开局前快照。  
输出：数值特征、地图类别特征和特征字典。

第一版特征组：

- 上下文：地图、回合号、双方比分、比分差。
- 经济：现金、装备价值及差值。
- 防具和道具：护甲、头盔、拆弹器、手雷。
- 武器：AK、M4、AWP、步枪、冲锋枪及差值。

双方存活人数继续保留在中间表用于质量检查，但合格开局样本恒为 5v5，
因此 `ct_alive`、`t_alive`、`alive_diff_ct` 不进入开局模型。

验收目标：

- 每个特征写明来源、类型、单位、取值范围和预测时是否可获得。
- 所有派生差值都有单元测试。
- 类别编码只在训练集拟合，验证/测试列与训练列严格对齐。
- 进行至少一次消融实验：比分、经济、武器三组分别移除并比较 AUC。

当前效果：正式模型使用 36 个模型前字段，地图独热编码后 43 列，没有缺失或常量列。
ESTA 的 `M4A1` 已正确映射为 M4A1-S。特征字典、全部差值测试、训练集类别词表
对齐测试均已完成；比分、经济、武器以及五组扩展消融已保存到
`reports/esta_full_m6`。正式 XGBoost 测试 AUC 为 0.7220。  
状态：完成。

### M7：简单基线模型

目的：证明 XGBoost 的提升来自模型和特征，而不是类别比例。

输入：同一份固定切分。  
输出：Dummy、逻辑回归和 XGBoost 的统一对比表。

验收目标：

- 保存“始终预测训练集 CT 胜率”的常数基线。
- 训练逻辑回归作为线性基线。
- 所有模型使用完全相同的测试集和指标函数。
- XGBoost 的测试 AUC 至少比逻辑回归高 0.01，或明确记录未提高。

当前效果：常数基线、逻辑回归和调优 XGBoost 已在相同测试行统一评估。三者测试
AUC 分别为 0.5000、0.727229 和 0.727122。XGBoost 相对逻辑回归为 -0.000107，
未达到 +0.01 性能目标，但已按规格明确记录；完整结果见 `docs/m7_baseline_spec.md`。
状态：流程完成；XGBoost AUC 增益目标未达到。

### M8：XGBoost 训练

目的：得到稳定且不过度拟合的模型。

输入：训练集和验证集。  
输出：模型、特征列、参数、随机种子和训练历史。

验收目标：

- 使用验证集 early stopping，而不是固定训练完 500 棵树。
- 保存最佳迭代轮数和完整参数。
- Train-Val AUC 差最低要求 <= 0.05，目标 <= 0.03。
- 重复训练指标差异 <= 0.002。
- CPU 版本先验收；GPU 只作为后续加速，不改变研究逻辑。

当前效果：控制变量实验选择 `max_depth=2`、`min_child_weight=3`，其余采样与正则参数
保持不变；使用 3000 棵上限和 100 轮 early stopping，最佳迭代为 212（213 棵树）。
Test AUC 为 0.7271、Log Loss 为 0.5917，Train-Val AUC 差降至 0.0111。
种子 42-46 的 Test AUC 最大差为 0.000748。完整参数、训练历史和实验表已保存。  
状态：完成。

### M9：统一评估

目的：从排序、分类和概率三个角度评价模型。

输入：固定测试集和模型概率。  
输出：CSV/JSON 指标、ROC 曲线、混淆矩阵和概率分布图。

验收目标：

| 指标 | 最低门槛 | 阶段目标 | 优秀目标 |
|---|---:|---:|---:|
| Test AUC | 0.70 | 0.73 | 0.75 |
| Test Log Loss | 0.61 | 0.58 | 0.56 |
| Test Accuracy | 0.64 | 0.66 | 0.68 |
| Test Brier Score | 0.21 | 0.195 | 0.185 |

同时报告 bootstrap 95% 置信区间，禁止只看一次点估计。

当前效果：固定测试集 AUC 0.727122、Log Loss 0.591733、Accuracy 0.647411、
Brier 0.205294，四项均达到最低门槛但均未达到阶段目标。已保存 4,172 行预测、
ROC、混淆矩阵、概率分布、可靠性曲线和 2,000 次系列赛级 bootstrap 95% CI；
AUC 区间为 [0.713125, 0.740907]。完整结果见 `docs/m9_evaluation_spec.md`。
状态：完成。

### M10：概率校准

目的：让模型输出的 70% 尽量接近真实约 70% 的获胜频率。

输入：验证集概率和测试集概率。  
输出：校准曲线、ECE、Brier Score，以及需要时的校准模型。

验收目标：

- Test ECE 最低 <= 0.04，目标 <= 0.03。
- 校准只使用验证集拟合，测试集只用于最终评价。
- 比较校准前后 Log Loss 和 Brier，不允许为了 ECE 明显损害其他指标。

当前效果：已比较不校准、Sigmoid 和 Isotonic。方法选择只使用按 `series_id`
分组的 5 折验证集 OOF 概率；原始概率以 Log Loss 0.596038、Brier 0.207575
优于两个校准候选，因此选择不校准。固定测试 ECE 为 0.023198，达到阶段目标；
完整结果见 `docs/m10_calibration_spec.md`。
状态：完成。

### M11：分组稳健性与误差分析

目的：确认模型不是只对某个数据来源或地图有效。

输入：测试集预测。  
输出：按地图、LAN/online、回合阶段和经济差分组的指标。

验收目标：

- LAN 与 online AUC 差 <= 0.04。
- 测试样本数 >= 300 的地图，AUC 最低 >= 0.67，目标 >= 0.69。
- 对高置信度错误预测至少抽查 30 个回合并分类原因。
- 小样本分组必须同时显示样本量和置信区间。

当前效果：LAN/online AUC 差为 0.009003，差值 95% CI 为
[-0.018130, 0.036925]。样本数 >= 300 的七张地图最低点估计为 Ancient 的
0.695993，达到目标；但最低地图 CI 下界为 0.658606。已分析 90 个高置信错误，
并逐条审查置信度最高的 30 个。与时点最接近的公开 DNN 相比，Accuracy 低
3.18 个百分点、Log Loss 高 0.023873；不同数据和切分使该差值不能解释为纯算法
差异。完整结果见 `docs/m11_robustness_spec.md`。
状态：完成。

### M12：模型解释

目的：说明哪些因素影响预测，并检查潜在泄漏或不合理规律。

输入：最终 XGBoost 和测试样本。  
输出：gain 特征重要性、Permutation Importance、SHAP 汇总图和单回合解释。

验收目标：

- 至少使用两种重要性方法，避免只依赖树的 gain。
- 对 CT 高胜率、T 高胜率和预测错误各提供案例。
- 检查前 20 个特征，确保没有未来信息或 ID 泄漏。
- 解释结果写入实验报告，而不只保存图片。

当前效果：已对固定 M8 模型生成部署树 Gain、20 次测试集 AUC Permutation
Importance 和 XGBoost 原生 TreeSHAP。`eq_value_diff_ct` 在三种方法中排名
2/1/1；全部 43 个输入和 SHAP 前 20 均无 ID 或未来信息。已解释 CT 高胜率、
T 高胜率和高置信错误各一个回合，SHAP 重建概率最大误差为 0.0000002512。
完整结果见 `docs/m12_explanation_spec.md`。
状态：完成。

### M13：预测接口

目的：让保存的模型能够对一条新回合快照输出胜率。

输入：符合字段要求的一行 JSON/CSV。  
输出：CT/T 获胜概率和输入校验信息。

验收目标：

- 缺字段、错误类型和超范围值给出明确错误。
- 输出的两个概率都在 0 到 1 之间且总和为 1。
- 保存并复用训练时的完整预处理步骤。
- 提供一个可直接运行的示例输入和预期输出格式。

当前效果：已提供 `predict_pre_round` 独立命令，支持一条 JSON 或 CSV。接口校验
27 个基础字段，自动生成 9 个 CT-T 差值，并复用训练时的预处理后按模型保存的
43 列对齐。JSON/CSV 示例概率完全一致；缺字段、错误类型、超范围、未知地图和
错误差值五类验收样本均被拒绝。示例输出 CT/T 概率和为 1。完整说明见
`docs/m13_prediction_interface_spec.md` 和 `reports/esta_full_m13/m13_interface_report.md`。
状态：完成。

### M14：测试、实验记录与阶段验收

目的：保证修改数据或特征后能够发现回归问题。

输入：上述全部模块。  
输出：自动化测试、一次完整运行记录和最终阶段报告。

验收目标：

- 为主键、快照、特征差值、分组切分、列对齐、指标和模型加载建立测试。
- 一条命令运行全部测试并通过。
- 每次实验记录数据版本、代码版本、参数、环境版本和指标。
- 每次阶段报告生成外部模型差值表，并明确标记是否可直接比较。
