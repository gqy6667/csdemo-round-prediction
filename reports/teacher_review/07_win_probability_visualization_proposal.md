# CS 回合胜率模型可视化方案报告

## 1. 目标与推荐结论

可视化不应只是把一个百分比放到比赛画面下方。它需要同时回答四个问题：

1. **现在谁更可能赢？**
2. **这个概率对应哪个真实预测时点？**
3. **模型为什么改变判断，两个模型是否一致？**
4. **这个数字能否追溯到数据、特征和冻结模型？**

推荐第一版采用：

> **模型审计页 + 单回合分析页 + 整场比赛回合带**

这三个界面可以直接复用当前已有的“购买结束”和“首杀后”模型，不需要重新训练。
直播底栏、烟雾弹后胜率、下包后胜率和残局胜率放在后续阶段，不能提前制造当前并不存在
的实时预测。

本文只保留 **A–G 共 7 个可行方案模块**。相似历史回合和敏感性分析作为这些模块内部
的可选功能，不再单独计算为新方案。

## 2. 当前能力边界

### 2.1 当前已有的真实模型节点

| 时点 | XGBoost | LightGBM | 当前能否显示胜率 |
|---|---|---|---|
| 购买结束、交火前 | 有 | 有 | 可以 |
| 最早有效敌对首杀刚发生 | 有 | 有 | 可以 |
| 第一颗烟雾弹投掷/爆炸 | 无 | 无 | 只能显示事件标记 |
| 首次伤害 | 无 | 无 | 只能显示事件标记或研究候选 |
| 下包后 | 无 | 无 | 只能显示事件标记 |
| 补枪后 | 无 | 无 | 只能显示事件标记 |
| 1vX/残局状态 | 无 | 无 | 只能显示事件标记 |

当前四份正式模型报告见 [项目报告总索引](README.md)。模型身份、数据与逐回合差异见
[模型更换验证报告](05_post_first_kill_model_replacement_verification.md)。

### 2.2 统一图例

- `●`：已有并通过验收的模型预测节点；
- `○`：数据中可观察的事件，但该时点没有胜率模型；
- `△`：计划中的未来预测模型；
- `!`：事件时间、特征或数据质量存在问题；
- `—`：两个模型判断接近；
- `≠`：两个模型出现预先定义的明显分歧。

### 2.3 绝不展示的内容

- 没有模型时点却生成一个看似精确的新胜率；
- 用平滑曲线暗示模型每秒都在预测；
- 把聚合指标的 bootstrap CI 当成单个回合概率区间；
- 把 SHAP 或特征重要性写成确定的战术因果；
- 直播模式提前显示最终胜方或未来事件；
- 为了“更有戏剧性”而放大微小模型差异。

### 2.4 七个方案总览

| 编号 | 方案 | 当前可行性 |
|---|---|---|
| A | 模型审计与验证页 | 当前可实现 |
| B | 单回合分析页 | 当前可实现 |
| C | 整场比赛回合带 | 当前可实现 |
| D | 直播底栏 | 后期，需要实时事件同步 |
| E | 模型分歧与错误实验室 | 当前可实现 |
| F | 地图战术与道具层 | 事件层可做，新胜率需要新模型 |
| G | 模型漂移与版本监控页 | 需要未来赛事数据 |

## 3. 一套数据支持七个方案

```text
原始回合与事件
      ↓
严格的预测时点特征快照
      ↓
XGBoost / LightGBM 冻结预测
      ↓
统一预测记录与审计信息
      ├── 模型审计页
      ├── 单回合分析页
      ├── 整场比赛回合带
      ├── 直播底栏
      ├── 模型分歧与错误实验室
      ├── 地图战术与道具层
      └── 模型漂移与版本监控页
```

统一数据源可以避免项目报告、论文图片和未来界面各自计算出不同的胜率。任何显示值都应
能沿下列路径追溯：

```text
页面数字 → 预测记录 → 模型 SHA256 → 特征快照 → 原始回合与事件
```

## 4. 方案 A：模型审计与验证页（优先级最高）

### 4.1 目标

让使用者在一个页面内确认：模型确实更换、比较公平、指标没有算错、结论没有超过证据。

### 4.2 页面草图

```text
首杀后模型审阅                                    [导出 PDF]
────────────────────────────────────────────────────
数据：41,027 回合 / 782 series     时点：首杀刚发生
split：547 / 156 / 79 series       特征：40 → 82

XGBoost                           LightGBM
模型类 / SHA / 409 trees          模型类 / SHA / 211 trees
────────────────────────────────────────────────────
五项指标对比          配对差值与 95% CI 森林图
────────────────────────────────────────────────────
预测相关散点图        绝对概率差分布
────────────────────────────────────────────────────
可靠性曲线            29 个分类分歧回合
────────────────────────────────────────────────────
数据质量 / 回放 / 测试 / 结论边界
```

### 4.3 必须包含

- 模型类型、内部库版本、SHA256、有效树数；
- 数据 SHA256、40/82 特征、split 行数和 `series_id` 数；
- XGBoost/LightGBM 五项指标并排；
- LightGBM 性能优势与配对 95% CI 森林图；
- 明确状态：“五项区间均包含 0，没有稳定显著胜者”；
- 两模型概率散点图及 `y=x` 参考线；
- 绝对概率差直方图和 P50/P90/P95；
- 0.5 阈值分类不一致回合列表；
- 回放误差、阻断检查和自动化测试结果；
- “模型替换成功”与“性能更好”分成两个独立结论卡片。

### 4.4 证据状态卡

不要给模型一个模糊总分，而是分开显示：

| 证据 | 状态示例 |
|---|---|
| 模型身份 | 通过：类和 SHA 不同 |
| 数据身份 | 通过：数据 SHA 冻结 |
| 防泄漏 | 通过：跨 split 重叠为 0 |
| 可复现 | 通过：冻结概率可回放 |
| 算法胜者 | 未确定：五项 CI 均含 0 |

这样不会把“没有胜者”误解成“整个实验失败”。

## 5. 方案 B：单回合分析页（推荐作为第一版交互界面）

### 5.1 页面草图

```text
比赛 / 地图 / 回合 / 当前比分                  [复盘模式]
────────────────────────────────────────────────────
CT 装备与经济       关键事件时间线       T 装备与经济

● 购买结束      CT 58% ━━━━━ 42% T
○ 烟雾弹爆炸    当前无该时点模型
● 首杀后        CT 71% ━━━━━ 29% T
○ 下包          当前无该时点模型

────────────────────────────────────────────────────
XGBoost 72.1% | LightGBM 71.4% | 相差 0.7 个百分点
模型关联因素 | 相似历史回合 | 数据质量 | 模型版本
```

### 5.2 核心交互

- CT 固定左侧、T 固定右侧，始终保存和展示 CT 胜率；
- `T 胜率 = 1 - CT 胜率`，不分别训练两个互相矛盾的概率；
- 点击 `●` 展开该预测时点实际使用的特征快照；
- 点击 `○` 查看事件参与者、时间和“为什么没有新胜率”；
- 在购买结束与首杀后之间使用阶梯线，不使用连续平滑曲线；
- 同时显示 XGBoost、LightGBM 及绝对差值；
- 复盘模式可以显示真实胜方，直播模式隐藏结果；
- 提供“上一回合/下一回合”和地图、阵营、经济筛选。

### 5.3 胜率变化解释

可以显示：

> CT 在购买结束时预测胜率为 58%。取得首杀后，首杀后模型给出 71%。

但不能直接写成：

> 这次首杀必然让 CT 胜率提高 13 个百分点。

两个时点来自不同特征快照和独立模型，变化是“模型预测差”，不是严格因果效应。解释区
应使用“关联因素”“模型敏感因素”“与历史样本相比”等措辞。

## 6. 方案 C：整场比赛回合带

### 6.1 目标

从单个回合扩大到整张地图，快速发现模型在哪些回合最自信、最容易错、分歧最大。

```text
Round      1  2  3  4  5  6  7  8  9 ...
买装备后   54 61 48 72 66 45 51 80 39 ...
首杀后     68 44 33 85 52 71 49 92 27 ...
实际胜方   C  T  T  C  T  C  C  C  T ...
模型分歧   ·  !  ·  ·  !  ·  ·  ·  · ...
```

推荐图形：

- 每个回合一个小矩形，颜色深浅表示 CT/T 倾向；
- 上下两行分别代表购买后和首杀后；
- 边框标记模型分歧，斜线标记高置信错误；
- 点击矩形进入单回合分析页；
- 支持只看手枪局、强起、eco、长枪局或加时回合。

这个界面当前可以实现，不需要新模型，适合从完整地图中寻找值得深入复盘的案例。

## 7. 方案 D：直播底栏（后期方案）

```text
CT 选手/装备 | CT 61% ━━━━━━━ 39% T | T 选手/装备
             XGB 61.2% / LGBM 60.8%
             最新节点：首杀后 · 更新于 4 秒前
```

直播版只保留最重要信息：

- 双方胜率；
- 最新真实预测节点；
- XGBoost/LightGBM 的差值；
- 装备与存活人数摘要；
- 更新时间、延迟和过期状态；
- 最新关键事件。

可以让数字在视觉上缓慢过渡，但底层必须从一个离散模型节点更新到另一个节点，并注明
最新预测时点。不得用动画暗示中间每秒都有新模型输出。

### 7.1 直播状态词

- `模型一致`：两模型绝对差低于预先冻结的阈值；
- `模型存在分歧`：超过阈值，但不代表某个模型错误；
- `数据更新延迟`：超过规定秒数未收到新事件；
- `事件已发生，暂无对应模型`；
- `数据质量不足，暂停显示胜率`。

## 8. 方案 E：模型分歧与错误实验室

这是最有研究价值的页面之一，专门研究总体指标隐藏的问题。

自动分组：

1. XGBoost 与 LightGBM 绝对概率差最大的回合；
2. 29 个 0.5 阈值分类不一致回合；
3. 两模型都高置信但错误的回合；
4. 一个模型正确、另一个错误的回合；
5. 预测接近 50% 的高不确定回合；
6. 某地图、经济档位或阵营中重复出现的错误；
7. 购买后判断正确、首杀后反而判断错误的回合；
8. 两个时点胜率变化最大的回合。

建议图表：

- 模型概率二维散点图；
- 离 `y=x` 最远的样本标注；
- 绝对差排行榜；
- 错误类型矩阵；
- 分地图/阵营/经济的小多图；
- 对应原始事件和特征快照的可追溯入口。

这个页面当前可以实现，不需要新模型。它也可以直接支持下一轮数据清洗和特征工程。

## 9. 方案 F：地图战术与道具层（未来方案）

在地图上叠加：

- 双方位置和移动轨迹；
- 烟雾弹投掷点、爆炸点与覆盖区域；
- 燃烧弹、闪光弹和 HE 事件；
- 关键交火和首杀位置；
- 已有模型节点的胜率卡片；
- 视线遮挡与可能路线（后期研究）。

当前只能把烟雾弹等道具作为事件显示，不能在地图节点旁生成新胜率。未来完成烟雾时点
模型后，才可以比较“烟雾爆炸前/后”的预测变化。

### 9.1 烟雾弹时点的三种定义

| 定义 | 优点 | 局限 | 建议 |
|---|---|---|---|
| 第一颗烟雾弹投掷 | 容易识别、时间早 | 烟雾尚未生效 | 只做事件标记 |
| 第一颗烟雾弹爆炸 | 定义清楚、已生效 | 不保证有战术价值 | 推荐作为第一版新模型时点 |
| 第一颗有效战术烟雾 | 最接近比赛意义 | 需地图区域、视线和人工定义 | 长期研究 |

第一版新增模型建议选择“第一颗烟雾弹爆炸”，并先做人工抽样检查。不要把“投掷”“爆炸”
和“产生有效遮挡”混为一个标签。

## 10. 方案 G：模型漂移与版本监控页

当模型真正用于新赛事时，需要回答它是否已经过时：

- 新赛事的装备、比分和地图分布是否偏离训练集；
- 各概率箱实际胜率是否仍与预测一致；
- 某地图或阵营的 Log Loss/ECE 是否恶化；
- XGBoost/LightGBM 分歧是否突然增大；
- 游戏版本、地图池或经济规则改变后是否需要重新训练。

建议显示：

- 特征漂移小多图；
- 新旧时间段可靠性曲线；
- 滚动 Log Loss、Brier 和 ECE；
- 模型版本切换时间线；
- 数据缺失与延迟监控。

这个页面需要未来赛事数据，但不一定需要新模型，适合部署阶段。

## 12. 不确定性必须分成三类

不要把所有信息压缩成一个没有定义的“可信度 82%”。

### 12.1 回合结果不确定性

预测接近 50%，说明当前特征下两边接近。可以显示“局势接近”，但不代表数据质量差。

### 12.2 模型不确定性

XGBoost 与 LightGBM 概率差较大。可以显示“模型存在分歧”，但在没有额外证据时不能
判定哪个模型正确。

### 12.3 数据支持不足

某地图、经济档位或事件组合历史样本过少，或事件时间/装备数据缺失。应显示样本量和
数据质量警告，而不是继续输出看似精确的数字。

聚合指标的 bootstrap CI 只描述模型整体性能差异，不能直接转换成某个回合的“61% ±
2%”。没有专门的单回合预测区间时，可以显示历史校准区间和样本数，但不能伪造区间。

## 13. 单回合页可选组件：相似历史回合

对当前回合寻找地图、阵营、比分、经济和装备最接近的历史回合，展示：

- 相似度依据；
- 历史样本数量；
- 历史 CT 实际胜率；
- 模型平均预测；
- 典型胜负案例。

必须标注“相似案例不是因果证据”。相似度只能使用预测时点前可获得特征，不能用结果或
未来事件参与检索。

## 14. 分歧实验室可选分析：模型敏感性

离线允许用户只改变一个输入，例如 CT 装备价值、AWP 数量或经济差，并观察模型输出。
它适合教学，但页面必须写成“模型敏感性测试”，不能写成“如果真的购买 AWP 就一定会
提高 X% 胜率”。

为避免构造不可能状态，需要：

- 限制在训练数据真实范围；
- 对相关特征联动或给出不现实组合警告；
- 显示最近真实样本距离；
- 不允许修改首杀后才知道的未来信息。

## 15. 事件与防泄漏合同

每个预测节点必须冻结：

- 事件名称及严格定义；
- 特征截止 tick/时间；
- 允许和禁止的特征；
- 缺失事件的处理；
- 标签定义；
- `series_id` 分组 split；
- 模型名称、类、SHA256 和库版本；
- 数据、特征顺序和校准器版本；
- 预测概率与 CT/T 视角；
- 回放和泄漏测试。

硬性规则：

- 特征只能来自预测时点或之前；
- 缺失事件不能用未来帧补齐；
- test 不参与调参、早停、校准或界面阈值选择；
- 新事件先做人工样本审计，再建模；
- 复盘与直播采用不同结果显示权限；
- 所有界面从同一冻结预测记录读取数值。

## 16. 视觉规范与可访问性

### 16.1 阵营与颜色

- 不仅依赖红/绿区分胜负，兼顾色觉差异；
- CT/T 同时使用文字、图标、位置和颜色编码；
- CT 始终左侧、T 始终右侧；
- 概率条中心明确标出 50%；
- 真实结果与预测使用不同视觉编码。

### 16.2 数字精度

- 直播：整数百分比或 1 位小数；
- 单回合分析：1 位小数；
- 模型审计和论文：保留 6 位指标或按报告标准；
- 不用过多小数制造不存在的确定性。

### 16.3 状态与延迟

- 显示最新预测时点；
- 显示最后更新时间；
- 超过阈值后标为“过期”；
- 数据缺失时隐藏或冻结概率，并解释原因。

## 17. 分阶段实施路线

| 阶段 | 交付内容 | 新模型 | 风险 |
|---|---|---|---|
| 0 | 页面信息架构、事件词典、字段与防泄漏合同 | 否 | 低 |
| 1 | 模型审计页：身份、指标、CI、校准、分歧 | 否 | 低 |
| 2 | 单回合分析页：两个真实节点与特征快照 | 否 | 中 |
| 3 | 整场比赛回合带 | 否 | 低–中 |
| 4 | 烟雾、下包、补枪等非预测事件标记 | 否，但需验证事件 | 中 |
| 5 | 第一颗烟雾弹爆炸后模型 | 是 | 高 |
| 6 | 下包、补枪、残局等独立模型 | 是 | 高 |
| 7 | 实时事件同步与直播底栏 | 可能需实时推理系统 | 高 |
| 8 | 统一事件驱动/时序模型与漂移监控 | 是 | 很高 |

推荐顺序：`模型审计页 → 单回合分析 → 整场概览 → 事件标记 → 新事件模型 →
直播`。

## 18. 第一版验收标准

第一版不是“能显示一个百分比”就完成，应至少满足：

1. 每个概率显示明确预测时点和 CT/T 视角；
2. 购买后与首杀后之间使用离散节点或阶梯线；
3. XGBoost/LightGBM 数字能与冻结 CSV 一一对应；
4. 模型审计页显示模型类、SHA、数据和 split；
5. 指标方向和 95% CI 与正式报告一致；
6. 烟雾弹等无模型事件明确写“暂无该时点模型”；
7. 复盘与直播模式不泄露未来结果；
8. 页面可以追溯到 `series_id + game_id + round_id`；
9. 缺失或过期数据有清晰状态。

## 19. 最终建议

现在最值得做的不是直接制作直播动画，而是先用当前冻结证据构建“模型审计页”和“单回合
分析页”。它们可以马上验证模型身份、展示真实的两个胜率节点，并为论文与项目复核提供
可靠材料。

建议第一版同时加入两个额外模块：

- **模型分歧与错误实验室**：帮助下一轮改进数据和特征；
- **整场比赛回合带**：把单回合结果放回完整比赛背景。

烟雾弹先作为灰色事件节点；等“第一颗烟雾弹爆炸”定义、数据和新模型全部通过防泄漏、
校准和冻结测试后，再开放对应胜率。这样既能得到接近电竞直播效果的界面，又不会为了
视觉连续性牺牲模型的科学可信度。
