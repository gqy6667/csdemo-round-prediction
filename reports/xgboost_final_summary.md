# XGBoost 阶段最终总结

## 1. 最终结论

本项目的 XGBoost 主线已经完成两个可使用、可复现的回合胜率模型：

1. **开局前模型**：购买完毕、冻结时间结束、正式交火前预测 CT 获胜概率；
2. **首杀后模型**：在同一购买快照上，加入最早有效敌对击杀的信息后再次预测。

M14 开局前最终验收 15/15 通过，M21 首杀后最终验收 17/17 通过。当前结论是
“工程闭环完成，可以进入 LightGBM 公平对照”，而不是“XGBoost 已经没有任何改进
空间”。开局前的更高研究目标仍未达到，首杀后的十项正式目标已经全部达到。

## 2. 最终数据合同

| 项目 | 开局前 | 首杀后 |
|---|---:|---:|
| 有效回合 | 41,074 | 41,027 |
| train | 28,522 | 28,489 |
| validation | 8,380 | 8,368 |
| test | 4,172 | 4,170 |
| 系列赛 | 782 | 782 |
| 原始特征 | 36 | 40 |
| 编码特征 | 43 | 82 |
| 跨 split 系列赛/游戏/回合 | 0 / 0 / 0 | 0 / 0 / 0 |

两项任务均使用按 `series_id` 分组的约 70/20/10 切分。ID、标签和 `split` 不进入
模型；类别编码只由训练集确定，validation/test 只对齐训练列。

首杀后比开局前少 47 回合，因为这些回合没有可接受的敌对首杀事件。它们不是被模型
随意删除，而是由 M15 的数据合同明确排除。

## 3. 最终测试指标

| 预测时点 | Accuracy | AUC | Log Loss | Brier | ECE10 |
|---|---:|---:|---:|---:|---:|
| 开局前 XGBoost（M14） | 0.647411 | 0.727122 | 0.591733 | 0.205294 | 0.023198 |
| 首杀后 XGBoost（M21） | 0.744125 | 0.809837 | 0.523146 | 0.175656 | 0.015450 |

从开局前到首杀后，AUC 原始增加 `0.082715`，Log Loss 下降 `0.068587`。这主要说明
首杀是强信息，不是单纯调参带来的提升，因为预测时点和输入信息已经改变。

## 4. 目标完成情况

### 开局前

| 指标 | 当前 | 最低门槛 | 更高目标 | 距更高目标 |
|---|---:|---:|---:|---:|
| Accuracy | 0.647411 | 0.640 | 0.660 | 还需 +0.012589 |
| AUC | 0.727122 | 0.700 | 0.730 | 还需 +0.002878 |
| Log Loss | 0.591733 | 0.610 | 0.580 | 还需下降 0.011733 |
| Brier | 0.205294 | 0.210 | 0.195 | 还需下降 0.010294 |

最低门槛 4/4 通过，更高目标 0/4。ECE10 `0.023198` 已低于 `0.030` 的校准目标。
这表示模型有稳定信号、概率质量达到阶段最低要求，但离更强的开局前模型仍有距离。

### 首杀后

十项正式目标 10/10 通过，剩余差距为 0。除五项点指标外，AUC 95% CI 下界、
Log Loss 95% CI 上界、LAN/online AUC 差、大地图最低 AUC 及其区间下界也全部通过。
其中 LAN/online 绝对 AUC 差为 `0.010276`。

## 5. XGBoost 调参实际带来了多少

| 同任务比较 | AUC 变化 | Log Loss 变化 | 解释 |
|---|---:|---:|---|
| M6 到 M14，开局前 | +0.005122 | -0.002026 | 数据质量、特征、评估和调参共同结果 |
| M16 未调参到 M21，首杀后 | +0.000941 | -0.001607 | 固定切分上的受控 XGBoost 调参 |

首杀后调参提升很小但方向稳定；它没有把测试集用于候选选择。项目最明显的性能进步
来自数据主键修复和新增合法的首杀信息，而不是不断堆叠树模型参数。

## 6. 与简单模型和公开结果的差距

开局前同切分逻辑回归 AUC 为 `0.727229`，XGBoost 为 `0.727122`，XGBoost 低
`0.000107`；它没有证明树模型在这个特征集合上天然优于线性模型。

最近的开局前公开 DNN 报告 Accuracy `0.679220`、Log Loss `0.567860`。本项目开局前
XGBoost 分别相差 `-3.18` 个百分点和 `+0.023873`，两项均较差。其数据和随机行切分
与本项目的 ESTA 系列赛分组切分不同，因此只能作为参考，不是公平排行榜。

最近的首杀后公开项目使用逻辑回归和 424 个个人回合。为保持模型族一致，本项目首杀后
逻辑回归 Accuracy `0.743405`、AUC `0.809059`，分别高 `6.10` 和 `4.91` 个百分点。
样本、切分和来源不同，同样不能把差值全部归因于模型。

## 8. 为什么可以进入 LightGBM

现在具备控制变量实验所需的前提：

- **输入稳定**：样本定义、主键、切分、特征和标签均已冻结；
- **参照稳定**：XGBoost 模型、测试概率和指标都能逐行回放；
- **评估稳定**：五项指标、最低门槛、外部比较规则和测试集使用规则固定；
- **环境稳定**：Python `3.10.20`、XGBoost `3.2.0`、LightGBM `4.6.0` 已锁定；
- **实验可归因**：下一步只替换训练算法，结果差异可以合理归因于模型实现与参数；
- **风险可控**：LightGBM 即使没有胜过 XGBoost，也不会破坏已经验收的 XGBoost 产物。

因此开始 LightGBM 不是推翻前面的工作，而是复用已验证的数据和评估管线，回答
“在完全相同条件下，另一种梯度提升树是否更适合这个任务”。M22 从开局前受控基线
开始；详细冻结规则见 `docs/m22_pre_round_lightgbm_baseline_spec.md`。

## 9. 尚未完成

- 尚未完成按比赛时间的真正外推切分；

- LightGBM 尚无正式同合同结果；
- 实时胜率的数据快照、时间轴和推理接口仍是之后的独立课题。

当前阶段顺序：**M22 开局前 LightGBM 基线 -> M23 LightGBM 验证集调参 -> 完整评估与
验收 -> 首杀后 LightGBM -> 实时胜率**。
